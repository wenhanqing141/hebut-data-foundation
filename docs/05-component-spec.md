# 组件使用规范（第一版）

## 1. 组件分层

### 基础组件

优先使用 Ant Design：`Button`、`Input`、`Select`、`DatePicker`、`Checkbox`、`Radio`、`Tag`、`Alert`、`Tooltip`、`Empty`、`Spin`、`Modal`、`Drawer`、`Table`、`Form`、`Pagination`、`Menu`、`Tabs`。

项目图标统一使用 IconPark，图标描边粗细统一为 `4px`；不得在单个图标上覆盖为其他粗细。

### 业务组件

第一批建议沉淀：

```text
PageHeader          页面标题、面包屑、主操作
FilterPanel         筛选条件和查询/重置
DataTable           数据表格、批量操作、分页
StatusTag           启用/停用/成功/失败/待处理
PermissionTree      分类、基础表、角色权限树
PermissionEditor    数据过滤和字段权限配置
ConfirmDangerModal  停用、删除等高风险确认
LogDetailDrawer     日志操作详情和记录级日志
```

## 2. 页面布局规范

### 管理后台

```text
顶部全局导航  56px
左侧模块导航  220-240px
页面内边距    24px
内容区最小宽度  1024px
```

基础数据中心后台采用“分类树 + 内容管理区”布局；接入中心采用“模块侧栏 + 筛选区 + 数据表格”布局。

### 前台数据页面

- 左侧只展示当前用户有权限的分类和基础表。
- 内容区优先展示当前表的名称、状态、数据操作和筛选条件。
- 低频操作进入更多菜单，避免工具栏横向拥挤。

## 3. 按钮规范

| 类型 | 使用场景 | 规则 |
|---|---|---|
| 主按钮 | 页面唯一主要动作 | 每个操作区尽量只有一个 |
| 次按钮 | 常规辅助动作 | 查询、导入、导出等 |
| 危险按钮 | 删除、永久清理 | 使用 `danger`，必须二次确认 |
| 警告按钮 | 停用、撤销 | 说明影响范围和恢复方式 |
| 链接按钮 | 行级查看、编辑 | 不承载高风险操作 |
| 图标按钮 | 排序、关闭、更多 | 必须有 Tooltip 和可访问名称 |

所有弹窗底部的确认和取消按钮统一使用 `88px` 宽度。

无提示语弹窗的顶部栏与内容区、内容区与底部栏之间的间距统一为 `24px`；有提示语时，标题与提示语间距为 `4px`，提示语与主体内容、主体内容与底部栏间距为 `24px`。

## 4. 表格规范

- 表格或表格型列表紧接上方标题/筛选区/工具栏时不额外留白（`0px`），与下方分页/操作区的间距统一为 `24px`；不得在单个页面使用不同的上下间距。
- 默认显示最常用字段，低频字段通过列配置管理。
- 首列可放选择框，末列放行级操作。
- 操作列优先保留“查看/编辑/删除”或“详情/授权”两到三个动作。
- 长文本使用省略号，悬浮显示完整内容；详情放抽屉。
- 敏感字段默认脱敏，不在列表中显示完整值。
- 空状态、加载状态、错误状态和筛选无结果必须分别设计。
- 大量字段时固定关键列，避免用户必须从左滚到右才能完成核心任务。

## 5. 高风险操作规范

### 启用

显示将生成哪些接口、哪些应用可能因此获得调用能力，以及确认后的生效范围。

### 停用

说明接口立即失效、调用方受到的影响，以及重新启用的恢复路径。

### 删除

显示不可恢复和级联清理的影响范围；要求输入完整表名；确认按钮在输入匹配前禁用。

## 6. 权限编辑器规范

- 左侧选择基础表或公共服务，右侧展示具体授权内容。
- 操作权限用明确的操作标签或分组表达：查询、新增、修改、删除。
- 数据过滤条件以“字段 + 运算符 + 值”的行形式编辑。
- 字段权限区分“可见字段”和“可编辑字段”，不能只用一个模糊的字段勾选区。
- 显示已选数量和授权生效提示。
- 授权变化需要明确保存按钮和保存成功反馈。

## 7. 日志规范

- 列表突出时间、操作人、操作类型、对象、结果。
- 详情优先展示操作上下文，再展示字段级变化。
- 成功和失败必须有文字，不只使用颜色。
- 失败详情需要说明失败原因和是否影响数据。
- 修改类日志应支持查看修改前/修改后内容；查询和导出类日志应说明“不涉及具体数据记录”。
