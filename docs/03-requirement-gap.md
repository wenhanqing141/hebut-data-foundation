# 需求疑问与原型差异清单

以下事项需要在进入高保真视觉设计前确认。未确认事项不应在 UI 中自行补全为确定业务规则。

## P0：影响页面结构或核心交互

| 编号 | 问题 | 当前依据 | 需要确认 |
|---|---|---|---|
| P0-01 | PRD 的统一日志目标包含访问、字段和修改前后内容，但原型的基础数据日志详情未明确展示所有修改前/后字段差异。 | PRD 第 2.2 节；日志原型 | 详情是否必须展示字段级 before/after、请求参数、响应结果和失败原因？ |
| P0-02 | PRD 要求授权视图按“应用视图”和“基础表视图”两个页面展示，当前应用管理原型主要呈现应用视图。 | PRD 2.1.2；应用管理原型 | 基础表视图是独立页面、Tab 还是后续版本？ |
| P0-03 | PRD 的字段权限同时涉及可见和可编辑，原型在操作级权限中展示字段勾选，但语义需要依赖当前操作推断。 | PRD 三、四；权限配置原型 | 查询对应可见，新增/修改对应可编辑是否为最终规则？删除是否不配置字段权限？ |
| P0-04 | 基础表创建页、表单字段配置页在五个原型中没有独立页面。 | PRD 五、1.1；初始化原型只有入口 | 本轮是否只设计入口和管理态，还是需要补齐创建/修改表单页面？ |
| P0-05 | 表单/审批引擎改造是 PRD 的重要范围，但没有对应页面原型。 | PRD 功能详细说明、通用功能影响 | 是否需要同时输出表单/审批引擎中“选择基础数据表”的页面状态？ |

## P1：影响信息架构、文案或状态

| 编号 | 问题 | 当前依据 | 需要确认 |
|---|---|---|---|
| P1-01 | PRD 写“日志管理：基础数据日志”，原型同时包含数据表日志和授权日志。 | PRD 功能范围；日志原型 | 数据表日志、授权日志是否本期正式交付？ |
| P1-02 | 应用管理原型包含“其他应用”和“公共服务”授权，PRD 对公共服务一期有明确说明，但其他应用接口的鉴权和自动授权仍待讨论。 | PRD 待讨论第 3 项；应用原型 | 其他应用接口是否一期上线，鉴权方式是什么？ |
| P1-03 | 原型使用“应用中心”“数据资产”等顶部导航，但本次 PRD 详细说明只覆盖数据基座和接入中心。 | 五个原型顶部导航 | 这些导航是可点击的正式模块，还是产品壳层占位？ |
| P1-04 | 原型存在导入、导出、审核、批量编辑等操作，但 PRD 未详细说明数据格式、权限和流程。 | 基础数据中心前后台原型 | 本期是否保留这些操作？每个操作的成功/失败/异步状态是什么？ |
| P1-05 | 删除基础表会同步清理接口、授权、数据和绑定关系，风险很高。 | PRD 1.1；删除确认原型 | 是否需要二次确认、管理员权限、审计提示和删除前影响范围预览？ |
| P1-06 | PRD 沟通记录确认需要镜像、登录信息同步和新域名，但没有页面层面的验收标准。 | 沟通记录 2026-10-21/20 | 这些是部署/研发事项，还是需要在原型中体现登录和环境切换？ |

## P2：视觉和实现层面

| 编号 | 问题 | 当前观察 | 处理建议 |
|---|---|---|---|
| P2-01 | 五个原型存在独立的颜色、按钮、表格和弹窗样式。 | 各文件 CSS 独立维护 | 统一迁移到 Ant Design Token 和项目级 CSS 变量，不直接复用原型 CSS。 |
| P2-02 | 原型大量使用 emoji、文本符号和内联 SVG 作为图标。 | 各文件按钮和弹窗 | 使用统一图标库和 Ant Design Icon，保证尺寸、语义和可访问性一致。 |
| P2-03 | 表格字段多且宽，原型主要依赖横向滚动。 | 基础数据表、授权视图、日志表格 | 设计固定列、字段优先级、列配置和详情抽屉，减少核心任务的横向负担。 |
| P2-04 | 原型中的示例数据包含较长字段、敏感字段、appid/appkey。 | 数据和授权原型 | 设计时区分脱敏展示、复制权限和开发示例数据，避免把密钥当普通文本展示。 |

## 结论

在 P0 问题确认前，可以先做全局布局、颜色 Token、基础组件和页面骨架；不建议开始最终的授权详情、日志详情和表单创建页高保真设计。
